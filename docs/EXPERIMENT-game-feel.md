“음악·효과 체험 전으로 돌려줘”라고 요청하면 된다. 이제 main에도 새 기능이 들어 있으므로 `git switch main`만으로는 이전 버전으로 복구되지 않는다. 정확한 이전 버전을 확인하려면 작업 파일이 깨끗한 상태에서 태그를 기준으로 별도 복구 브랜치를 만든다(기존 브랜치를 덮어쓰거나 force-push하지 않는다).

```sh
git switch -c codex/restore-before-game-feel backup-before-game-feel-2026-09-08
```

main의 기능을 되돌릴 때는 이후 변경 사항을 먼저 확인하고 체험 커밋 `4b3b488`을 `git revert`하는 새 커밋으로 처리한다. 대기화면 음악 등 후속 변경도 원래 음악 재생 기능에 의존하므로, 전체 체험 기능을 복구할 때는 해당 후속 변경의 의존 관계와 되돌릴 순서를 함께 확인한다. 복구 브랜치 생성만으로 원격 main이 바뀌지는 않는다. main 반영 문서도 복구 상태에 맞춰 갱신한다.

체험판으로 다시 전환:

```sh
git switch codex/game-feel-music
npm run dev -- --host 127.0.0.1 --port 5189
```

미커밋 작업이 있으면 먼저 별도 보관하고 전환한다. `reset --hard`는 사용하지 않는다. 음악 설정은 기존 preferences에 필드 하나를 추가하며 기록은 `taptopick.records.v1`에 별도 저장한다. 원래 버전은 이 추가 데이터를 무시한다. 복구할 때 사용자의 다른 설정이나 브라우저 데이터를 지울 필요가 없다.

## 체험 범위

1. 정답: 220ms 눌림·복원, 연속 정답에 따른 짧은 상승음. 오답이면 연속음 리셋. 일반 정답 효과가 새 입력 지연을 추가하지 않는다.
2. 완성: 게임1은 컬러 완성 그림 1.1초 감상→기존 캐릭터 영상→결과. 게임2 승급 850ms·기존 보너스 하트 효과. 게임3 완성된 단계만 750ms 감상하며 다음 단계 제한시간을 소모하지 않는다. 성공과 실패 소리·문구 구분. 영상은 Continue로 바로 넘길 수 있다.
3. 결과: 이번 기록, 이 기기의 최고 기록, 다음 목표, Play again/Home. 게임1은 캐릭터·조각 수별 시간 기록, 게임2는 발견 수, 게임3은 단계·페어·시간 순서. 저장 불가 시 세션 기록으로 전환하고 안내한다. 로그인·클라우드 동기화는 없다.
4. 음악(최초 체험판): 오리지널 합성곡 Pick Garden, 100 BPM, C major, 38.4초 반복. 웹 MP3 약 560KB, 첫 플레이 때 지연 로딩. 최초 버전은 메뉴·일시정지·영상·결과·숨긴 탭에서 중지했다. Settings 및 일시정지의 Music 버튼으로 끌 수 있으며 효과음과 독립 설정이다. 현재 메뉴 동작은 아래 후속 변경을 따른다.

앨범/수집 기능은 이번 범위에 포함하지 않았다. `src/core/pick/`의 점수·보드·생명·제한시간 규칙도 바꾸지 않았다. 스테이지 감상 시간은 완료된 보드에서만 UI가 보류한다.

## 후속 변경 — 대기화면 음악 (2026-09-08)

- 메인 대기화면과 메뉴에서 연 Settings·How to play에서도 음악을 재생한다. 첫 터치 또는 키 입력을 받아 브라우저 오디오를 활성화한 뒤 시작하며, 사용자 입력 전 자동 재생을 강제하지 않는다.
- 메뉴곡은 같은 멜로디·화성·16마디를 유지한 **Pick Garden — Menu**다. 템포만 100→92 BPM으로 조금 낮추고 마림바의 높은 배음을 부드럽게, 퍼커션의 횟수와 세기를 절반으로 조정했다. 약 41.74초 반복이며 웹 MP3는 424,330바이트다.
- 실제 게임으로 들어가면 기존 100 BPM 곡으로 전환한다. 원곡 WAV·JSON은 생성기 기본 옵션으로 다시 생성해도 기존 해시와 일치하며, 원곡 MP3도 수정하지 않았다. 메뉴·게임 음악이 겹쳐 계속 재생되지 않도록 화면 전환을 관리한다.
- 일시정지·캐릭터 영상·결과 화면과 숨긴 탭에서는 음악을 중지한다. Music 켜기/끄기는 메뉴곡과 게임곡에 공통 적용하며 효과음 설정과는 계속 독립이다.
- `src/ui/sceneMusic.ts`가 화면별 음악 라우팅과 중복 재생 방지를 담당하고, 기존 `src/ui/backgroundMusic.ts`는 디코딩·반복·볼륨 전환을 담당하는 재생기로 유지한다. 생성기 `--menu` 옵션으로 별도 WAV·JSON을 만든 뒤 FFmpeg로 MP3를 인코딩하며, 검증기는 두 곡의 WAV·MP3 네 파일을 각각의 메타데이터에 맞춰 검사한다.
- 규칙·점수·생명·스테이지·기존 결과 연출은 변경하지 않는다. 새 메뉴 음악만 되돌릴 경우에는 `5626b24` 이후 해당 변경만 확인해 되돌리고, 전체 체험 전 태그로 돌아가지 않는다.
